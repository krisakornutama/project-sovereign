เลือกแฟ้มใบเสร็จ (JSON) หรือแฟ้มเอกสารบัญชี (JSONL จาก ledger export) — หน้านี้ตรวจลายเซ็นทีละชั้น Ed25519 · ML-DSA-44 (FIPS 204) · SLH-DSA (FIPS 205) และสาย hash ของแฟ้มบัญชี ทั้งหมดบนเครื่องคุณ — ไม่ต้องติดตั้งโปรแกรม ไม่ต้องใช้บริการตรวจของใคร

แฟ้มไม่ถูกอัปโหลดไปที่ใด — ปิดอินเทอร์เน็ตก็ตรวจได้เมื่อเปิดหน้านี้แล้วครั้งแรก (เสิร์ฟแบบ PWA)

เลือกแฟ้มที่จะตรวจ

รับทั้งใบเสร็จเดี่ยว (.json) และแฟ้มเอกสารบัญชี (.jsonl — ตรวจสาย hash ทีละบรรทัด + ลายเซ็นซองฝังของทุกใบ)

🖱️ คลิกเลือกแฟ้ม (หรือลากมาวางที่นี่)
รับ: ใบเสร็จ .json · แฟ้มเอกสารบัญชี .jsonl
เกณฑ์การตรวจ (ผู้ตรวจทั่วไปอ่านก่อนเชื่อ) 
ใบเสร็จ 1 ใบ (.json)
  1. แกนของใบครบ (id / issued_at / payload / alg_profile)
  2. bytes ที่ถูกเซ็น = canonical JSON ของแกน (เรียงคีย์ · ไม่มีช่องว่าง)
  3. Ed25519      — ตรวจด้วย WebCrypto ของเบราว์เซอร์ (กุญแจสาธารณะฝังในใบ)
  4. ML-DSA-44    — ตรวจด้วย @noble/post-quantum (context "sovereign-pq-receipt/v1")
  5. SLH-DSA-128s — โปรไฟล์สามชั้นเท่านั้น · ต้องมีและผ่านด้วย (ขาด = ใบไม่สมบูรณ์)
  ผ่าน = ทุกชั้นของโปรไฟล์จริงในใบ — ขาด/แก้ payload ตำแหน่งเดียว = ปฏิเสธ

แฟ้มเอกสารบัญชี (.jsonl · sovereign.accounting-ledger.v1)
  1. โครง 3 ชนิดบรรทัด: header → doc (ใบละหนึ่งบรรทัด) → footer
  2. สาย hash ทุกบรรทัด: SHA-256("sovereign-accounting-chain/v1" ‖ 0x00 ‖ h_prev ‖ 0x00 ‖ canonical)
     → แก้ payload ใบใด / ตัดใบ / สลับลำดับ / แก้ยอดรวม = สายพังทันที
  3. ทุก doc ตรวจลายเซ็นซองฝังใหม่ทุกชั้น (เทียบ receipt_sha256 = SHA-256 ของซอง)
  4. header/footer จำนวนตรงเอกสารจริง · footer ยอดรวมตรงผลรวม (หรือ null ถ้ามีใบไม่มียอด)
