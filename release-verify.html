release verification

ตรวจว่าไฟล์ที่คุณดาวน์โหลดคือไบต์ที่เราลงนามไว้

ทุก release ของ Sovereign OS แนบเอกสาร sovereign-attest.json ที่เซ็นด้วยกุญแจ Ed25519 ไว้ด้วย หน้านี้ประกาศ กุญแจสาธารณะ และ fingerprint ของกุญแจนั้น ไว้บนเว็บนี้ ซึ่งเป็นคนละช่องทางกับ repository — ถ้าบัญชี GitHub ถูกยึด ผู้โจมตีจะแก้ไฟล์ได้ แต่แก้ fingerprint ที่ประกาศไว้ที่นี่ไม่ได้พร้อมกัน

กุญแจ release ที่ใช้ตรวจ

fingerprint (32 hex แรกของ SHA-256 ของ SPKI)

1afcc7d951d822a7dfe384d89209aed2

public key (Ed25519, PEM)

-----BEGIN PUBLIC KEY-----
MCowBQYDK2VwAyEA/T3GybhH+pXie2L4BAn/pIjGfTIUhg5+IDRNH6KK4Hs=
-----END PUBLIC KEY-----

ไฟล์เดียวกันนี้ดาวน์โหลดได้ที่ attest-release.pub.pem — ถ้าค่าที่คุณเห็นไม่ตรงกับที่อื่นที่คุณเชื่อถือ ให้หยุดทันที

วิธีตรวจ (3 ขั้น)

  1. โหลดเอกสารใบรับรอง — sovereign-attest.json จากหน้า Release เดียวกับไฟล์ที่คุณดาวน์โหลด
  2. โหลดตัวตรวจ — สองไฟล์ ไม่มี dependency: 
    curl -fsSL --create-dirs -o verifier/tools/attest-release.mjs \
  https://raw.githubusercontent.com/krisakornutama/sovereign-origin/main/tools/attest-release.mjs
curl -fsSL --create-dirs -o verifier/tools/attest/document.mjs \
  https://raw.githubusercontent.com/krisakornutama/sovereign-origin/main/tools/attest/document.mjs
  3. วางไฟล์ไว้ในโฟลเดอร์เดียวแล้วรัน — ต้องมี Node 20 ขึ้นไป: 
    sov-attest/
  Sovereign-OS-…-portable.exe
  Sovereign-OS-…-win-x64.zip
  sovereign-attest.json

node verifier/tools/attest-release.mjs --verify sov-attest/sovereign-attest.json \
  --fingerprint=1afcc7d951d822a7dfe384d89209aed2 --dir=sov-attest

คำสั่งนี้ตรวจสามชั้น: ลายเซ็นของทุกใบรับรอง, การต่อ chain ของแต่ละไฟล์ และแฮชของไบต์จริงในโฟลเดอร์ (ขนาดและ sha256) — ไม่มีการต่อเน็ตระหว่างตรวจ

อ่านผลลัพธ์อย่างไร

  • ผ่าน — ไฟล์ที่คุณถืออยู่คือไบต์เดียวกับที่เซ็นไว้ และลายเซ็นมาจากกุญแจด้านบน
  • ไม่ผ่าน — อย่าติดตั้ง ให้ลบไฟล์แล้วดาวน์โหลดใหม่ ถ้ายังไม่ผ่านอีก แปลว่าช่องทางดาวน์โหลดถูกแก้ ให้แจ้งผู้พัฒนา
  • ไฟล์ที่ไม่ได้ถูกเซ็น — ตัวตรวจจะบอกแยก เช่นไฟล์ที่คุณเพิ่มเอง ไม่ทำให้ผลรวมไม่ผ่าน แต่ควรรู้ว่ามันไม่ได้อยู่ในใบรับรอง

อย่าใช้ SHA256SUMS.txt เป็นหลักฐานแทน — ไฟล์นั้นมากับที่เดียวกับไฟล์ติดตั้ง ใครแก้ช่องทางดาวน์โหลดได้ก็แก้ทั้งคู่พร้อมกันได้ fingerprint ข้างบนคือสิ่งที่ต้องมาจากช่องทางอื่น

ถ้าบิลด์ถูกเพิกถอน

ผู้พัฒนาลงนามเพิกถอนบิลด์ที่พบปัญหาได้ และระบุวันที่มีผลได้ (เพิกถอนเฉพาะของที่ปล่อยก่อนวันนั้น ไม่เหวี่ยงทั้งประวัติ) ตัวตรวจจะปฏิเสธบิลด์ที่ถูกเพิกถอนให้เอง — อย่าใช้ --allow-revoked เว้นแต่คุณตั้งใจดูหลักฐานของบิลด์ที่ถูกถอนจริง ๆ

รายละเอียดทั้งหมด (การหมุนกุญแจ การเพิกถอน และข้อจำกัดที่ยังเหลือ) อยู่ใน docs/SOVEREIGN-ATTEST.md และหน้า fingerprint ที่ repository หลัก: krisakornutama.github.io/sovereign-origin/release-verify.html

หน้านี้เป็นช่องทางที่สองนอก GitHub โดยเจตนา — fingerprint ที่ประกาศซ้ำในช่องทางที่แยกจากที่เก็บโค้ด ทำให้การยึดบัญชีเดียวไม่พอจะปลอมทั้งไฟล์และกุญแจ · กลับหน้าภาพรวม
